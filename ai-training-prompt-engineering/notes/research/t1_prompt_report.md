## 1. Core definitions (Section 1.1 + 1.2.2, https://arxiv.org/html/2406.06608v6)

- **Prompt** (§1.1): "A prompt is an input to a Generative AI model, that is used to guide its output." Prompts may consist of text, image, sound, or other media; usually have some text component. (Examples given: "write a three paragraph email for a marketing campaign for an accounting firm"; a photo of paper reading "what is 10*179"; a meeting recording plus "summarize this".)
- **Prompt Template** (§1.1): "A prompt template is a function that contains one or more variables which will be replaced by some media (usually text) to create a prompt. This prompt can then be considered to be an instance of the template." Example template: `Classify the tweet as positive or negative: {TWEET}`. Figure 1.2 caption: "Prompts and prompt templates are distinct concepts; a prompt template becomes a prompt when input is inserted into it." (Template example pair: `Write a poem about trees.` = prompt; `Write a poem about the following topic: {USER_INPUT}` = template.)
- **Prompting** (§1.2.2): "the process of providing a prompt to a GenAI, which then generates a response."
- **Prompt Chain** (§1.2.2): "two or more prompt templates used in succession. The output of the prompt generated by the first prompt template is used to parameterize the second template, continuing until all templates are exhausted." (activity: prompt chaining)
- **Prompting Technique** (§1.2.2): "a blueprint that describes how to structure a prompt, prompts, or dynamic sequencing of multiple prompts. A prompting technique may incorporate conditional or branching logic, parallelism, or other architectural considerations spanning multiple prompts."
- **Prompt Engineering** (§1.2.2): "the iterative process of developing a prompt by modifying or changing the prompting technique that you are using." Figure 1.4: the process = repeat (1) perform inference on a dataset, (2) evaluate performance, (3) modify the prompt template; an extractor pulls the final response from LLM output.
- **Prompt Engineering Technique** (§1.2.2): "a strategy for iterating on a prompt to improve it" — often automated in the literature, often manual in consumer settings.
- **Exemplar** (§1.2.2): "Exemplars are examples of a task being completed that are shown to a model in a prompt."
- Scope note (§2.1): survey covers **hard (discrete) prefix prompts** only; hard prompts contain only tokens corresponding to words in the model's vocabulary (vs. soft prompts); gradient-based/fine-tuning techniques excluded.
- Appendix A.1 contains a table of competing prompt / prompt-engineering definitions from ~20 other papers (Meskó 2023, Chen et al. 2023a, White et al. 2023, etc.) that the authors integrated to derive their representative definitions. Appendix A.8 gives a formal treatment ("As a conditioning mechanism", "Templating", "Few-Shot Prompting", "Optimization", "Other considerations").

## 2. Components of a Prompt (§1.2.1) — the paper's prompt anatomy (closest academic match to an element model)

Exact component list, verbatim order and names (https://arxiv.org/html/2406.06608v6 §1.2.1: "There are a variety of common components included in a prompt. We summarize the most commonly used components"):

1. **Directive** — "Many prompts issue a directive in the form of an instruction or question. This is the core intent of the prompt, sometimes simply called the 'intent'." Can be explicit (`Tell me five good books to read.`) or **implicit** (one-shot case where the directive is implied: `Night: Noche\nMorning:` = English→Spanish translation). Term borrowed from Searle 1969 speech acts.
2. **Examples** — "Examples, also known as exemplars or shots, act as demonstrations that guide the GenAI to accomplish a task." (One-Shot = one example.)
3. **Output Formatting** — "It is often desirable for the GenAI to output information in certain formats, for example, CSV, Markdown, XML, or even custom formats." Notes the debate: structuring outputs may reduce performance on some tasks (Tam et al. 2024) but may actually improve it (Kurt 2024). Example phrasing: `{PARAGRAPH}\nSummarize this into a CSV.`
4. **Style Instructions** — "Style instructions are a type of output formatting used to modify the output stylistically rather than structurally." Example phrasing: `Write a clear and curt paragraph about llamas.`
5. **Role** — "A Role, also known as a persona, is a frequently discussed component that can improve writing and style text." Example phrasing: `Pretend you are a shepherd and write a limerick about llamas.`
6. **Additional Information** — "It is often necessary to include additional information in the prompt. For example, if the directive is to write an email, you might include information such as your name and position so the GenAI can properly sign the email." **The paper explicitly discourages calling this 'context'** "as it is overloaded with other meanings in the prompting space" (e.g., context = tokens processed by the LLM in a forward pass).

### One-line definitions for appendix terms (Appendix A.2, https://arxiv.org/html/2406.06608v6)

- **Context Window** (A.2.1): "the space of tokens (for LLMs) which the model can process. It has a maximal length (the context length)."
- **Priming** (A.2.1): "giving a model an initial prompt that lays out certain instructions for the rest of a conversation" — might contain a role or interaction instructions; can be done in the system or user prompt.
- **Conversational Prompt Engineering** (A.2.2): "Prompt Engineering in colloquio" — during a conversation, the user asks the GenAI to refine its output (vs. sending a completely new prompt).
- **Prompt-Based Learning** (A.2.3): a.k.a. Prompt Learning — "the process of using prompting-related techniques", often in a fine-tuning context; authors avoid the term due to conflicting usage.
- **Prompt Tuning** (A.2.3): "directly optimizing the weights of the prompt itself, usually through some form of gradient-based updates" (a.k.a. Prompt Fine-Tuning); should not be used to mean discrete prompt engineering.
- **User Prompt** (A.2.4.1): the prompt that comes from the user — most common form in consumer applications.
- **Assistant Prompt** (A.2.4.1): the output of the LLM itself, considered a prompt (or part of one) when fed back into the model, e.g., as conversation history.
- **System Prompt** (A.2.4.1): "used to give LLMs high level instructions for interacting with users. Not all models have this."
- **Hard (discrete) Prompt** (A.2.4.2): contains only tokens that directly correspond to words in the LLM vocabulary.
- **Soft (continuous) Prompt** (A.2.4.2): contains tokens that may not correspond to any vocabulary word; used when fine-tuning full weights is too expensive (gradients flow through prompt tokens). Paper notes Hard Prompts ⊆ Soft Prompts.
- **Cloze** (A.2.4.3): prediction style where the token(s) to predict are "slots to fill", usually mid-prompt (BERT-era models).
- **Prefix** (A.2.4.3): prediction style where the token to predict is at the end of the prompt (modern GPT-style models).

## 4. Text-based prompting technique taxonomy (§2.2) — the "58 techniques, 6 categories"

Paper statement (§2.2): "We now present a comprehensive taxonomical ontology of **58 text-based prompting techniques, broken into 6 major categories** (Figure 2.2). Although some of the techniques might fit into multiple categories, we place them in a single category of most relevance."

**Category-name verification.** In the **v6 Figure 2.2** (PDF p.9) the six top-level branches are: **Zero-Shot, Few-Shot, Thought Generation, Decomposition, Ensembling, Self-Criticism**. In the v6 **section structure**, Zero-Shot and Few-Shot are both nested under **2.2.1 In-Context Learning (ICL)** (2.2.1.2 Few-Shot Prompting Techniques; 2.2.1.3 Zero-Shot Prompting Techniques), followed by 2.2.2 Thought Generation, 2.2.3 Decomposition, 2.2.4 Ensembling, 2.2.5 Self-Criticism. (Earlier revisions listed In-Context Learning and Zero-Shot as the two separate top categories; v6's figure uses Zero-Shot/Few-Shot.)

**ICL definition** (§2.2.1): "ICL refers to the ability of GenAIs to learn skills and tasks by providing them with exemplars and or relevant instructions within the prompt, without the need for weight updates/retraining." Note: "learn" is misleading — ICL can simply be task specification. (Appendix A.9 disambiguates against Brown et al. 2020's definitions.)
**Few-Shot Prompting** (§2.2.1): the paradigm where the GenAI learns to complete a task with only a few exemplars; a special case of Few-Shot Learning without parameter updates. Canonical template (Fig. 2.7): `{Exemplars}\nD_x^test:`
**Zero-Shot Prompting** (§2.2.1.3): uses zero exemplars.

### 4.1 Few-Shot Prompting Design Decisions (§2.2.1.1, Figure 2.3) — six decisions + starred recommendations

(Figure 2.3 caption: "We highlight six main design decisions when crafting few-shot prompts. *Please note that recommendations here do not generalize to all tasks; in some cases, each of them could hurt performance.")

1. **Exemplar Quantity** — recommendation: "Include as many exemplars as possible*". More exemplars generally helps (benefits may diminish beyond ~20; long-context LLMs keep benefiting).
2. **Exemplar Ordering** — recommendation: "Randomly order exemplars*". Order affects behavior; can swing accuracy from sub-50% to 90%+ (Lu et al. 2021).
3. **Exemplar Label Distribution** — recommendation: "Provide a balanced label distribution*". Skewed label distribution biases the model.
4. **Exemplar Label Quality** — recommendation: "Ensure exemplars are labeled correctly*". Evidence mixed on whether incorrect labels hurt; larger models more robust.
5. **Exemplar Format** — recommendation: "Choose a common format*". Most common: `Q: {input}, A: {label}`; formats common in training data perform better.
6. **Exemplar Similarity** — recommendation: "Select similar exemplars to the test instance*". Similar exemplars generally help; sometimes diverse ones do.

Plus a seventh discussion item in v6: **Instruction Selection** (§2.2.1.1) — generic, task-agnostic instructions (or none) can beat task-specific ones in few-shot prompts (Ajith et al. 2024); instructions still guide auxiliary attributes like writing style.

### 4.2 Complete technique tree with one-line descriptions (all from §2.2, https://arxiv.org/html/2406.06608v6)

**In-Context Learning (ICL) → Few-Shot Prompting Techniques (§2.2.1.2)** — figure groups these under Few-Shot as Exemplar Generation / Exemplar Selection etc.:
- **K-Nearest Neighbor (KNN)** (Liu et al. 2021) [exemplar selection] — selects exemplars similar to the test input to boost performance; can be time/resource intensive.
- **Vote-K** (Su et al. 2022) [exemplar selection] — model proposes useful unlabeled candidates for an annotator to label; labeled pool then used for few-shot prompting while ensuring diversity/representativeness.
- **Self-Generated In-Context Learning (SG-ICL)** (Kim et al. 2022) [exemplar generation] — uses the GenAI itself to auto-generate exemplars when training data is unavailable.
- **Prompt Mining** (Jiang et al. 2020) — discovers optimal "middle words"/template formats through large-corpus frequency analysis (corpus-frequent formats perform better).
- (Mentioned as "more complicated techniques": **LENS** (iterative filtering), **UDR** (embedding & retrieval), **Active Example Selection** (RL) — named but not counted as main entries.)

**In-Context Learning (ICL) → Zero-Shot Prompting Techniques (§2.2.1.3)** (figure top-level "Zero-Shot"):
- **Role Prompting** (a.k.a. persona prompting) — assigns a specific role to the GenAI ("act like Madonna" / "a travel writer"); improves open-ended output and sometimes benchmark accuracy.
- **Style Prompting** (Lu et al. 2023a) — specifies desired style, tone, or genre in the prompt.
- **Emotion Prompting** (Li et al. 2023a) — adds phrases of psychological relevance to humans (e.g., "This is important to my career").
- **System 2 Attention (S2A)** (Weston & Sukhbaatar 2023) — first asks the LLM to rewrite the prompt removing irrelevant info, then answers the cleaned prompt.
- **SimToM** (Wilf et al. 2023) — for multi-person/object questions: first establish the set of facts one person knows, then answer based only on those facts (two-prompt process).
- **Rephrase and Respond (RaR)** (Deng et al. 2023) — instructs the LLM to "Rephrase and expand the question, and respond" before answering.
- **Re-reading (RE2)** (Xu et al. 2023) — adds "Read the question again:" plus a repetition of the question.
- **Self-Ask** (Press et al. 2022) — LLM first decides if follow-up questions are needed, generates and answers them, then answers the original question.

**Thought Generation (§2.2.2)** — "techniques that prompt the LLM to articulate its reasoning while solving a problem":
- **Chain-of-Thought (CoT) Prompting** (Wei et al. 2022b) — few-shot exemplars featuring question + reasoning path + answer, encouraging the LLM to express its thought process. Example (Fig 2.8): `Q: Jack has two baskets... A: One basket contains 3 balls, so two baskets contain 3*2=6 balls. Q: {QUESTION} A:`
- *Zero-Shot-CoT (§2.2.2.1)* — CoT with zero exemplars via a thought-inducing phrase, e.g., "Let's think step by step." (Kojima et al. 2022), "First, let's think about this logically", "Let's work this out in a step by step way to be sure we have the right answer" (Zhou et al. 2022b).
  - **Step-Back Prompting** (Zheng et al. 2023c) — first ask a generic, high-level question about relevant concepts/facts, then reason.
  - **Analogical Prompting** (Yasunaga et al. 2023) — auto-generates exemplars that include CoTs (similar to SG-ICL).
  - **Thread-of-Thought (ThoT)** (Zhou et al. 2023) — improved thought inducer: "Walk me through this context in manageable parts step by step, summarizing and analyzing as we go." Good for large/complex contexts.
  - **Tabular Chain-of-Thought (Tab-CoT)** (Jin & Lu 2023) — zero-shot CoT that outputs reasoning as a markdown table.
- *Few-Shot CoT (§2.2.2.2)* — exemplars include chains-of-thought (a.k.a. Manual-CoT, Golden CoT):
  - **Contrastive CoT Prompting** (Chia et al. 2023) — adds exemplars with both incorrect and correct explanations to show how not to reason.
  - **Uncertainty-Routed CoT Prompting** (Google 2023, Gemini) — samples multiple CoT paths; takes majority if above a threshold, else greedy sample.
  - **Complexity-based Prompting** (Fu et al. 2023b) — select complex exemplars for the prompt; at inference, majority-vote among longer reasoning chains.
  - **Active Prompting** (Diao et al. 2023) — compute uncertainty on training questions; humans rewrite the highest-uncertainty exemplars.
  - **Memory-of-Thought Prompting** (Li & Qiu 2023b) — pre-compute CoT inference on unlabeled exemplars; retrieve similar instances at test time.
  - **Automatic Chain-of-Thought (Auto-CoT)** (Zhang et al. 2022b) — uses zero-shot CoT to auto-generate chains of thought to build a few-shot CoT prompt.
  - **AutoDiCoT (Automatic Directed CoT)** (paper's own, §6.2.3.3; appears in v6 Figure 2.2) — auto-generates directed CoTs explaining why items were labeled a certain way (from the case study); shown in the figure under Few-Shot CoT.

**Decomposition (§2.2.3)** — "decomposing complex problems into simpler sub-questions":
- **Least-to-Most Prompting** (Zhou et al. 2022a) — break a problem into sub-problems without solving; solve sequentially, appending responses each time.
- **Decomposed Prompting (DECOMP)** (Khot et al. 2022) — few-shot shows the LLM how to use functions (string splitting, internet search, etc.); LLM routes sub-problems to those functions.
- **Plan-and-Solve Prompting** (Wang et al. 2023f) — improved zero-shot CoT: "Let's first understand the problem and devise a plan to solve it. Then, let's carry out the plan and solve the problem step by step."
- **Tree-of-Thought (ToT)** (Yao et al. 2023b; also Long 2023) — tree search over thoughts; evaluates each step's progress via prompting and decides which branches to continue. Effective for search/planning tasks.
- **Recursion-of-Thought** (Lee & Kim 2023) — hard sub-problems encountered mid-chain are sent to another prompt/LLM call; answer is inserted back (handles context-length limits).
- **Program-of-Thoughts** (Chen et al. 2023d) — generates code as reasoning steps; a code interpreter executes them (strong for math/programming, weak for semantic reasoning).
- **Faithful Chain-of-Thought** (Lyu et al. 2023) — CoT with both natural-language and symbolic (e.g., Python) reasoning, task-dependent symbolic languages.
- **Skeleton-of-Thought** (Ning et al. 2023) — generate a skeleton of the answer (sub-problems), solve them in parallel, concatenate.
- **Metacognitive Prompting** (Wang & Zhao 2024) — five-part prompt chain mirroring human metacognition: clarify question, preliminary judgement, evaluate response, decision confirmation, confidence assessment.

**Ensembling (§2.2.4)** — "using multiple prompts to solve the same problem, then aggregating these responses into a final output" (often majority vote):
- **Demonstration Ensembling (DENSE)** (Khalifa et al. 2023) — multiple few-shot prompts with distinct exemplar subsets; aggregate outputs.
- **Mixture of Reasoning Experts (MoRE)** (Si et al. 2023d) — diverse reasoning experts via specialized prompts per reasoning type (retrieval-augmented for factual, CoT for math/multi-hop, generated-knowledge for commonsense); best answer by agreement score.
- **Max Mutual Information Method** (Sorensen et al. 2022) — multiple templates with varied styles/exemplars; select the template maximizing mutual information between prompt and outputs.
- **Self-Consistency** (Wang et al. 2022) — sample multiple CoT paths at non-zero temperature; majority vote the final answer.
- **Universal Self-Consistency** (Chen et al. 2023e) — like Self-Consistency, but a prompt (not program) selects the majority answer; works for free-form generation.
- **Meta-Reasoning over Multiple CoTs** (Yoran et al. 2023) — generate multiple reasoning chains, insert all into one prompt, generate final answer from them. (Figure label: "Meta-CoT".)
- **DiVeRSe** (Li et al. 2023i) — multiple prompts × Self-Consistency each; score reasoning paths step-by-step to select final response.
- **Consistency-based Self-adaptive Prompting (COSP)** (Wan et al. 2023a) — build few-shot CoT prompts from high-agreement zero-shot-CoT+Self-Consistency outputs; run Self-Consistency again.
- **Universal Self-Adaptive Prompting (USP)** (Wan et al. 2023b) — generalizes COSP to all tasks using unlabeled data and a more complex scoring function; no Self-Consistency.
- **Prompt Paraphrasing** (Jiang et al. 2020) — transform a prompt by rewording while preserving meaning; data augmentation for building ensembles.

**Self-Criticism (§2.2.5)** — "have LLMs criticize their own outputs":
- **Self-Calibration** (Kadavath et al. 2022) — answer, then a new prompt asks whether the answer is correct (confidence gauging for accept/revise decisions).
- **Self-Refine** (Madaan et al. 2023) — iterative: LLM gives feedback on its answer, then improves it; repeat until stopping condition.
- **Reversing Chain-of-Thought (RCoT)** (Xue et al. 2023) — reconstruct the problem from the generated answer; compare against the original to find inconsistencies as feedback. (Figure label: "ReverseCoT".)
- **Self-Verification** (Weng et al. 2022) — multiple CoT candidate solutions; score each by masking parts of the question and predicting them from the solution.
- **Chain-of-Verification (COVE)** (Dhuliawala et al. 2023) — generate answer; create list of verification questions; answer them; produce final revised answer.
- **Cumulative Reasoning** (Zhang et al. 2023b) — generate candidate steps; LLM accepts/rejects each; check if final answer reached; iterate.

## 5. Prompt Engineering techniques (§2.4) — automated prompt optimization

- **Meta Prompting** — "prompting a LLM to generate or improve a prompt or prompt template". Simple template (Fig. 2.12): `Improve the following prompt: {PROMPT}`.
- **AutoPrompt** (Shin et al. 2020b) — frozen LLM + template with "trigger tokens" updated via backprop (soft prompting).
- **Automatic Prompt Engineer (APE)** (Zhou et al. 2022b) — generate multiple zero-shot instruction prompts from exemplars, score, create variations of the best (e.g., via prompt paraphrasing), iterate.
- **Gradientfree Instructional Prompt Search (GrIPS)** (Prasad et al. 2023) — like APE with a richer operation set: deletion, addition, swapping, paraphrasing.
- **Prompt Optimization with Textual Gradients (ProTeGi)** (Pryzant et al. 2023) — pass batches through the template; a criticism prompt critiques the original prompt; new prompts generated from criticisms; bandit algorithm selects one.
- **RLPrompt** (Deng et al. 2022) — frozen LLM + unfrozen module trained with Soft Q-Learning to generate templates (often selects grammatically nonsensical optimal prompts).
- **Dialogue-comprised Policy-gradient-based Discrete Prompt Optimization (DP2O)** (Li et al. 2023b) — RL + custom prompt scoring function + conversations with an LLM to construct the prompt.

## 6. Answer Engineering (§2.5) — three design decisions

"Answer engineering is the iterative process of developing or selecting among algorithms that extract precise answers from LLM outputs." Three design decisions:
1. **Answer Shape** (§2.5.1) — the physical format of the answer: a token, span of tokens, image, video; e.g., restrict to a single token for binary classification.
2. **Answer Space** (§2.5.2) — the domain of values the answer may contain: all tokens, or e.g. just two tokens for binary labeling.
3. **Answer Extractor** (§2.5.3) — a rule to extract the final answer when the answer space can't be fully controlled:
   - **Verbalizer** — maps output token/span to a label and vice-versa (e.g., "+"/"-" → positive/negative).
   - **Regex** — search for first (or, with CoT, last) instance of a label.
   - **Separate LLM** — an LLM extracts the answer, often via an **answer trigger** ("The answer (Yes or No) is").

## 7. Beyond English text (§3) — the "40 techniques for other modalities"

### 7.1 Multilingual (Figure 3.1 / §3.1)
- **Translate First Prompting** (Shi et al. 2022) — translate non-English inputs to English first.
- Multilingual CoT: **XLT (Cross-Lingual Thought) Prompting** (six-instruction template incl. role assignment, cross-lingual thinking, CoT); **CLSP (Cross-Lingual Self Consistent Prompting)** (ensemble of reasoning paths in different languages).
- Multilingual ICL: **X-InSTA Prompting** (semantic / task-based / combined alignment of exemplars); **In-CLT (Cross-lingual Transfer) Prompting** (exemplars use both source and target languages).
- In-Context Example Selection: **PARC (Prompts Augmented by Retrieval Cross-lingually)** — retrieve exemplars from a high-resource language.
- Prompt Template Language Selection: **English Prompt Template** (usually stronger, due to English-heavy pretraining) vs. **Task Language Prompt Template** (used in language-specific benchmarks; human-translated beats machine-translated).
- Machine translation: **MAPS (Multi-Aspect Prompting and Selection)** (knowledge mining → multiple candidate translations → select); **CoD (Chain-of-Dictionary)** (prepend multilingual dictionary chains); **DiPMT** (dictionary defs in source/target languages only); **DecoMT** (chunk the source, translate chunks, combine). Human-in-the-loop: **ICP (Interactive-Chain-Prompting)** (GenAI asks disambiguating sub-questions, humans answer); **Iterative Prompting** (draft translation refined with retrieval/human feedback).

### 7.2 Multimodal (Figure 3.2 / §3.2)
- Image: **Prompt Modifiers** (words appended to change the generated image — components like Medium "on canvas", Lighting "a well lit scene"); **Negative Prompting** (numerically down/up-weight terms, e.g., negative "bad hands").
- Multimodal ICL: **Paired-Image Prompting** (before/after transformation pair, then new image); **Image-as-Text Prompting** (generate a textual description of the image for inclusion in a text prompt).
- Multimodal CoT: **DDCoT (Duty Distinct Chain-of-Thought)** (multimodal Least-to-Most); **Multimodal Graph-of-Thought**; **Chain-of-Images (CoI)** ("Let's think image by image", generates SVGs to reason visually).
- Also covered as prompting areas without named techniques: Audio Prompting (§3.2.2), Video Prompting (§3.2.3, incl. video generation techniques), Segmentation Prompting (§3.2.4), 3D Prompting (§3.2.5).

## 8. Extensions: Agents & Evaluation (§4)

**Definition of Agent** (§4.1): "we define agents to be GenAI systems that serve a user's goals via actions that engage with systems outside the GenAI itself." (Excludes independently-acting AI with its own goals.) Agent systems frequently involve memory, planning, and actions.

Agent technique tree (§4.1, headings + one-liners):
- *Tool Use Agents* (4.1.1): **MRKL System** (LLM router with access to multiple tools; combines calls into a final response — Toolformer, Gorilla, Act-1 similar); **CRITIC (Self-Correcting with Tool-Interactive Critiquing)** (generate → self-criticize → verify/amend with tools).
- *Code-Generation Agents* (4.1.2): **PAL (Program-aided Language Model)** (translate problem directly into code, run in interpreter); **ToRA (Tool-Integrated Reasoning Agent)** (interleaves code and reasoning steps); **TaskWeaver** (user requests → code, supports user-defined plugins).
- *Observation-Based Agents* (4.1.3): **ReAct** (thought → action → observation loop, all kept in prompt memory); **Reflexion** (ReAct + introspective reflection on success/failure as working memory). *Lifelong Learning Agents* (4.1.3.1): **Voyager** (self-proposed tasks, code execution, long-term memory of actions); **GITM (Ghost in the Minecraft)** (recursive subgoal decomposition, structured-text actions, knowledge base + memory).
- *Retrieval Augmented Generation (RAG)* (4.1.4): "a paradigm in which information is retrieved from an external source and inserted into the prompt". **Verify-and-Edit** (edit CoTs with retrieved info); **Demonstrate-Search-Predict** (decompose → query → combine); **IRCoT** (interleave CoT and retrieval for multi-hop QA); **Iterative Retrieval Augmentation** (FLARE, IRP — repeated plan-sentence → retrieve → inject during long-form generation).

Evaluation-as-prompting (§4.2): prompting techniques for LLM judges = **In-Context Learning, Role-based Evaluation, Chain-of-Thought, Model-Generated Guidelines**; output formats = **Styling (e.g., XML/JSON), Linear Scale (1-5), Binary Score, Likert Scale**; frameworks = **LLM-EVAL, G-EVAL, ChatEval**; other = **Batch Prompting, Pairwise Evaluation**.

## 9. Prompting Issues (§5) — brief (security/alignment vocabulary)

- Security (§5.1): **Prompt Hacking** types = **Prompt Injection** (untrusted user input overrides developer instructions) and **Jailbreaking** (getting the model to bypass its safety training); risks incl. **Training Data Reconstruction, Prompt Leaking, Package Hallucination, Bugs**; hardening = **Prompt-based Defenses, Detectors, Guardrails**.
- Alignment (§5.2): **Prompt Sensitivity** (small changes/task format/prompt drift), **Overconfidence & Calibration** (verbalized score, sycophancy), **Biases** (vanilla prompting, balanced demonstrations, cultural awareness, AttrPrompt), **Ambiguity** (ambiguous demonstrations, question clarification).
