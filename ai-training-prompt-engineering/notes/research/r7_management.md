# R7 — Storing, Managing, Versioning, and Sharing Prompts (business teams first, engineering second)

Research notes for corporate AI training, medical-device supplier/quality + business audience.
All facts verified against sources as of **August 21, 2026** unless marked UNVERIFIED. Source URLs inline.

---

## Part A — Why manage prompts at all

### The core argument: prompts are reusable assets, not throwaway text

- **Anthropic's framing (primary vendor source):** Skills exist because prompts are "conversation-level instructions for one-off tasks," while packaged, reusable instructions "load on demand, so you don't have to repeat the same guidance across conversations." Key benefits Anthropic lists: specialize the AI, reduce repetition ("create once, use automatically"), compose capabilities (source: https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview). Anthropic explicitly describes a skill folder as "organized like an onboarding guide you'd create for a new team member" (same URL) — **analogy: technically defensible and directly quotable.**
- **Anthropic Academy tutorial:** "Skills let you package what you've learned. Then, whenever the context matches, Claude applies the expertise automatically." Its explicit trigger for formalizing: *when you find yourself explaining the same task multiple times, it's time to create a skill* (source: https://academy.claude.com/tutorials/teach-claude-your-way-of-working-using-skills — redirected from https://support.claude.com/en/articles/12580051-teach-claude-your-way-of-working-using-skills).
- **Ethan Mollick (credible practitioner, Wharton):** In "Now is the time for grimoires" (Aug 2023, still widely cited in 2026) he argues companies should build "libraries of prompts, grimoires of expert spells that allow practices to be scaled inside the organization... prompts that encode our hard-earned expertise in ways that AI can help other people apply" (source: https://www.oneusefulthing.org/p/now-is-the-time-for-grimoires). His minimal org stack: AI access for everyone + a Slack channel & wiki page to collect prompts + a culture that rewards sharing. See also "Innovation through prompting" (source: https://www.oneusefulthing.org/p/innovation-through-prompting). **Analogy: "grimoire"/spell book — memorable but mystical; use lightly. The safer teaching analogy for this audience: a prompt library is a set of controlled SOPs/work instructions — a name, an owner, a revision, a review date. (Process analogy only, not a regulatory claim.)**
- **Microsoft (primary vendor source):** Copilot Prompt Gallery exists so "prompts can be saved and shared across teams... to promote consistency and collaboration" (source: https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-prompt-gallery, page dated 2026-02-06, updated 2026-08-18).
- **OpenAI (primary, by product design):** Workspace agents (Apr 2026) are positioned as making AI "a shared organizational resource rather than individual productivity tool," with a team directory of shared agents (source: https://openai.com/index/introducing-workspace-agents-in-chatgpt/; summary via https://venturebeat.com/orchestration/openai-unveils-workspace-agents-a-successor-to-custom-gpts-for-enterprises-that-can-plug-directly-into-slack-salesforce-and-more).
- **Practitioner writing on team prompt libraries:** a prompt library is "a structured, shared collection of reusable AI instructions — an AI playbook": pull a tested, approved template, fill in the variables, get consistent results; captures institutional knowledge; helps new hires learn "how the company uses AI" (sources: https://aicamp.so/blog/why-team-needs-shared-prompt-libraries/, https://teamai.com/blog/prompt-libraries/building-a-prompt-library-for-my-team/, https://www.airops.com/blog/build-reusable-prompt-library, https://textexpander.com/blog/ai-prompt-library-guide).
  - Note: circulating stats like "43% faster task completion / 62% more consistent output (TextExpander 2025 enterprise survey)" appear only in secondary blogs; **UNVERIFIED — do not present as fact.** TextExpander's own guide gives only an illustrative arithmetic example (100 inquiries/day x 3 min saved = 300 min/day), not survey data (source: https://textexpander.com/blog/ai-prompt-library-guide).

### The three teachable reasons (each sourced above)
1. **Reuse** — a good prompt took iteration to produce; re-typing from memory throws that work away (Anthropic: "create once, use automatically").
2. **Consistency** — a team using one tested template gets comparable outputs; Microsoft's stated purpose for Prompt Gallery sharing is exactly "consistency and collaboration."
3. **Iteration** — versions let you improve a prompt deliberately and roll back when a change makes it worse (see Part D registries; also Anthropic Console eval workflow, Part C/D).

**Teaching line: "Prompts are the new snippets/SOPs" — supported by the sources above as a synthesis; label it as the course's framing, not a quote.**

## Part B — Business-team mechanisms (product facts verified Aug 2026)

### B1. Personal level
- **Saved-prompts doc:** the zero-infrastructure baseline — a personal doc/OneNote/Notion page of best prompts. Recommended as the starting point by practitioner guides (source: https://textexpander.com/blog/ai-prompt-library-guide, https://www.airops.com/blog/build-reusable-prompt-library).
- **Text expanders (TextExpander and similar):** store prompts as snippets that "insert anywhere you type" via abbreviations; shared Snippet Groups give teams one library where "when someone improves a prompt, the update reaches the entire team automatically"; supports fill-in fields (variables) and revision history showing "what changed, when, and by whom" (source: https://textexpander.com/blog/ai-prompt-library-guide).

### B2. ChatGPT (OpenAI)
- **Custom instructions:** persistent guidance applied across chats; editable; separate from Memory (static text you set vs. facts ChatGPT accumulates). One active global set at a time (sources: https://help.openai.com/ articles as summarized by search; help.openai.com blocked direct fetch — details below cross-checked with press). As of 2025 reporting, global custom instructions ~1,500 chars/field (free) (secondary sources: https://sqmagazine.co.uk/chatgpt-projects-free-access-update/ — **char limits UNVERIFIED against OpenAI primary; present without exact numbers**).
- **Projects:** dedicated workspaces holding related chats + uploaded files + **project-level custom instructions that override global instructions inside that project**, plus project-only memory. Launched Dec 2024 for paid plans; extended to free users Sept 2025 (file caps by plan: ~5 free / 25 Plus / 40 Pro-Business-Enterprise, per Sept 2025 coverage) (sources: OpenAI help center https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt [fetch blocked, existence confirmed]; press: https://alternativeto.net/news/2025/9/chatgpt-projects-now-available-to-free-users-with-more-file-uploads, https://beebom.com/chatgpt-projects-come-to-free-users-organize-chats-and-files-in-one-place/). **Exact current limits: verify live in the product before teaching.**
- **Custom GPTs:** a saved, shareable configuration (instructions + knowledge files + tools). In Business/Enterprise/Edu workspaces GPTs can be shared with specific people, the whole workspace, by link, or published to the GPT Store, subject to admin settings (source: https://help.openai.com/en/articles/8798878-sharing-and-publishing-gpts; https://help.openai.com/en/articles/8555535-managing-gpt-access-in-enterprise-and-edu-workspaces). GPT Store still operating in 2026 with private workspace sections for Team/Enterprise (source: https://openai.com/index/introducing-the-gpt-store/).
- **IMPORTANT Aug-2026 status change:** On **April 22, 2026** OpenAI announced **workspace agents** as the successor to custom GPTs for organizations: agents that use connected apps (Slack, Salesforce, Drive), remember, and run multi-step work; discovered/managed via an Agents tab; OpenAI is **deprecating the custom-GPT standard for org plans** at a future unspecified date (individual GPTs continue) (sources: https://openai.com/index/introducing-workspace-agents-in-chatgpt/, https://venturebeat.com/orchestration/openai-unveils-workspace-agents-a-successor-to-custom-gpts-for-enterprises-that-can-plug-directly-into-slack-salesforce-and-more). Teach custom GPTs as "current but transitioning to agents on business plans."

### B3. Claude (Anthropic)
- **Projects:** self-contained workspaces with own chat history, knowledge files, and **project instructions** ("rules Claude follows for every conversation inside that project"). Free accounts: up to 5 projects; paid plans unlimited; Team/Enterprise projects can be **shared with the organization** (source: https://support.claude.com/en/articles/9517075-what-are-projects; corroborating summaries in search results, Aug 2026).
- **Claude Skills (launched Oct 16, 2025):** a skill is a **folder with a SKILL.md file** (plus optional scripts/, references/, assets/). SKILL.md has YAML frontmatter with required `name` (max 64 chars, lowercase/hyphens) and `description` (max 1024 chars — must say *what it does and when to use it*). **Progressive disclosure, 3 levels:** (1) metadata always loaded (~100 tokens per skill), (2) SKILL.md body loaded when triggered (<5k tokens), (3) bundled files/scripts loaded/run only as needed — so you can install many skills "without context penalty" (source: https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview). Announcement: https://claude.com/blog/skills (redirect from anthropic.com/news/skills), Oct 16, 2025.
  - **Where:** claude.ai (custom skills uploaded as zip via Settings > Features; Pro/Max/Team/Enterprise with code execution; **individual to each user, no org-wide admin distribution on claude.ai**), Claude API (workspace-wide via /v1/skills), Claude Code (folders in `~/.claude/skills/` personal or `.claude/skills/` project — shareable via git) (source: same overview page).
  - **When to promote a prompt to a skill (Anthropic's own guidance):** regular prompting for one-offs; **create a skill when you've explained the same task multiple times**, when you've refined an approach and want consistency, when quality depends on specific materials (brand guidelines, templates), or when setup requires assembling multiple pieces. Projects = accumulated evolving context; custom instructions = universal preferences; skills = repeatable procedures applied automatically (source: https://academy.claude.com/tutorials/teach-claude-your-way-of-working-using-skills).
  - Security note for governance section: Anthropic says treat installing a skill "like installing software" — audit skills from outside sources (source: https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview).
- **Styles:** preset response styles (Concise, Explanatory, Formal) plus custom styles created from sample content or a description — controls *how* Claude writes, reusable across chats (launched Nov 2024; still current) (sources: https://www.maginative.com/article/anthropic-introduces-custom-writing-styles-for-claude-ai/, https://x.com/AnthropicAI/status/1861474224151445927).
- **Teaching ladder for Claude:** one-off prompt → style (tone) → project instructions (context + rules for an area of work) → skill (packaged procedure, auto-applied) — each step is a promotion of a prompt into a more durable asset (synthesis of the two Anthropic sources above).

### B4. Gemini (Google)
- **Gems:** saved Gemini configurations — name + instructions (Google recommends Persona/Task/Context/Format in instructions) + optional knowledge files (PDF/Word/Google Docs); "Use Gemini to re-write instructions" wand assists drafting (source: https://support.google.com/gemini/answer/15235603).
- **Gem sharing (Sept 2025):** Workspace users can share Gems "with other users in your organization and beyond," Drive-style (viewer/editor permissions); shared Gems appear in a "Gemini Gems" Drive folder protected by Drive permissions; admin toggle under Generative AI > Gemini app > Gems (sources: https://workspaceupdates.googleblog.com/2025/09/gem-sharing-gemini-app-workspace.html, https://techcrunch.com/2025/09/18/google-now-lets-you-share-your-custom-gemini-ai-assistants-known-as-gems/, https://9to5google.com/2025/09/18/share-gemini-gems/).
- **New (Apr 14, 2026):** Gemini in Chrome added **saved-prompt "Skills"** — save any prompt as a reusable template, invoke with "/" or "+", edit title/text; Google shipped 50+ pre-built skills (sources: https://siliconangle.com/2026/04/14/google-adds-reusable-prompts-gemini-chrome/, https://thenewstack.io/gemini-chrome-saved-prompts/). Note the naming collision with Anthropic's (heavier-weight) Skills — worth a slide callout.

### B5. Microsoft Copilot (M365)
- **Copilot Prompt Gallery:** catalog inside Copilot/Copilot Chat with **Suggested** (Microsoft-curated), **Your Prompts** (user-saved), and **Teams** (team-shared) tabs. Save any prompt with a title; share via copy link, email, or to a Microsoft Teams team; team members see shared prompts in the Prompts app under "Team prompts" (sources: https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-prompt-gallery [dated 2026-02-06]; https://techcommunity.microsoft.com/blog/microsoft365copilotblog/new-copilot-prompt-gallery-helps-you-discover-save-and-share-your-favorite-promp/4279600; https://support.microsoft.com/en-us/office/learn-about-copilot-prompts/sharing-prompts-with-a-team). Practitioner tip when saving: replace details that change each run with **[bracketed variables]** (source: https://custom365.co/%F0%9F%92%BE-how-to-save-and-share-prompts-in-microsoft-copilot/ — secondary).
  - Admin/compliance: prompts are stored in user/group collections in the Microsoft 365 Substrate data store, **within the tenant boundary**, encrypted; admins can export what users saved/liked/shared (sources: https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-prompt-gallery, https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-prompt-gallery-export-prompts).
- **Copilot agents:** no-code **Agent Builder** inside M365 Copilot — describe an agent in natural language or configure instructions/tone/scope; ground in SharePoint, Teams, Outlook, OneDrive; share with specific users or the org; multiple owners supported; plus SharePoint agents, Copilot Studio, and pro-code declarative agents (sources: https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/agent-builder, https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/agent-builder-share-manage-agents).

### B6. DIY prompt-library database (Notion / SharePoint list / Confluence)
- Practitioner consensus pattern: a shared database/list, one row per prompt (sources: https://aicamp.so/blog/why-team-needs-shared-prompt-libraries/, https://teamai.com/blog/prompt-libraries/building-a-prompt-library-for-my-team/, https://www.airops.com/blog/build-reusable-prompt-library, https://textexpander.com/blog/ai-prompt-library-guide). **Fields worth tracking** (synthesized from those sources + document-control practice; present as course recommendation):
  - Name (descriptive, prefixed by function, e.g. "SQE — Supplier audit summary")
  - Purpose / when to use (one line)
  - Prompt text (the blank template with {{variables}})
  - Owner (a person, not a team)
  - Version + date + change note
  - Model(s) tested on (e.g. "Claude Sonnet 4.6, GPT-5.x, Aug 2026") — prompts behave differently per model
  - Last-tested date
  - Example filled prompt + example output (gold standard)
  - Status (draft / approved / retired)
- Start with high-friction repetitive tasks; appoint "Prompt Champions"; surface the library where people work (Teams/Slack link) (source: https://aicamp.so/blog/why-team-needs-shared-prompt-libraries/).

## Part C — Template conventions (course patterns; grounding noted per item)

- **{{placeholder}} variables:** separate the fixed template from per-run inputs. Anthropic's own prompt-engineering docs use `{{DOUBLE_BRACKET}}` variables inside XML-tagged templates (e.g. `{{ANNUAL_REPORT}}`, `{{PATIENT_SYMPTOMS}}`) (source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices). Langfuse/PromptLayer registries use the same mustache-style `{{variable}}` insertion (sources: https://langfuse.com/docs/prompt-management/overview, https://www.promptlayer.com/prompt-management/). Microsoft's ecosystem uses [square-bracket] fill-ins in Prompt Gallery saves (secondary: https://custom365.co/%F0%9F%92%BE-how-to-save-and-share-prompts-in-microsoft-copilot/). **Analogy: mail-merge fields in a form letter — technically defensible.**
- **[OPTIONAL: ...] blocks:** mark sections to delete when not needed (e.g. "[If supplier is critical: add risk-class table]"). Course convention; no single canonical source — consistent with TextExpander "fill-in fields" and Copilot bracket practice.
- **Versioning (v1.0 + changelog):** registries do this automatically (Langfuse: incrementing version numbers + labels like `production`/`staging`; PromptLayer: "Git-style immutability with diffs, commit messages, and instant rollback") (sources: https://langfuse.com/docs/prompt-management/overview, https://www.promptlayer.com/prompt-management/). Business teams replicate it manually: version field + one-line change note per revision; TextExpander guide: keep revision history of "what changed, when, and by whom" (source: https://textexpander.com/blog/ai-prompt-library-guide). **Analogy for this audience: document revision control (Rev A/B/C + change description) — same discipline, lighter weight. Defensible as practice analogy.**
- **"Reuse by diff":** for a recurring job, don't rewrite — reuse last time's prompt and state only what's different ("same as monthly scorecard prompt, but for Q3 and flag the two new suppliers"). Course-coined term (label it as such); mechanically it's what project instructions/skills do for you automatically (Anthropic: skills exist "so you don't have to repeat the same guidance" — https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview).
- **One-metric-card / glossary pattern:** keep a standard block defining your team's metrics/abbreviations (e.g. what "PPM," "NCR," "SCAR" mean, how OTD is computed) and paste/attach it to any analysis prompt so every teammate's prompt uses identical definitions. Course pattern; grounded in Google's Context element for Gem instructions (https://support.google.com/gemini/answer/15235603) and knowledge-files features across vendors.
- **Store filled examples next to blank templates:** a gold-standard filled prompt + its output shows new users what "good" looks like; Anthropic's skill guidance likewise asks for "one successful example that demonstrates your standards" (source: https://academy.claude.com/tutorials/teach-claude-your-way-of-working-using-skills); TextExpander guide recommends notes on expected results (source: https://textexpander.com/blog/ai-prompt-library-guide).
- **Test before promoting:** run the candidate prompt on 3–5 representative real cases (including one edge case) before marking it "approved." Tool support: Anthropic Console **Evaluate** tool — build test-case suites (generate/manual/CSV import), run all cases in one click, compare outputs of prompt versions **side by side**, grade on a 5-point scale (sources: https://docs.claude.com/en/docs/test-and-evaluate/eval-tool, https://www.anthropic.com — feature coverage: https://sdtimes.com/ai/anthropic-adds-prompt-evaluation-feature-to-console/, https://siliconangle.com/2024/07/10/anthropic-expands-developer-console-creating-evaluating-ai-prompts/).
- **Ownership & review cadence:** every approved prompt has a named owner; review on a cadence (e.g. quarterly, and after any model change) because model updates silently change behavior — this is why registries record which model a version was tested against (sources: practitioner guides above; Langfuse/PromptLayer version-model tracking). Present cadence numbers as course recommendation, not sourced fact.

## Part D — Engineering-grade (brief)

- **Prompts-as-code in git:** keep agent instructions in the repo next to the code they govern.
  - **CLAUDE.md** — file Claude Code reads at the start of every conversation; holds build commands, style, workflow rules; generated via `/init`, refined over time; keep concise and reviewed (source: https://code.claude.com/docs/en/best-practices).
  - **.claude/ folders** — project-scoped skills in `.claude/skills/`, subagents in `.claude/agents/*.md` (YAML frontmatter), all versioned with the project (sources: https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview, https://code.claude.com/docs/en/best-practices).
  - **AGENTS.md** — open cross-vendor format ("a README for agents"), released Aug 2025 by OpenAI with Codex/Amp/Jules/Cursor/Factory, now stewarded by the Agentic AI Foundation under the Linux Foundation; used by 60k+ open-source projects (sources: https://agents.md/, https://github.com/agentsmd/agents.md, https://socket.dev/blog/agents-md-gains-traction-as-an-open-format-for-ai-coding-agents).
  - The point for business audience: engineers already treat prompts as version-controlled, code-reviewed files — the same discipline the library brings to business prompts.
- **Prompt registries & observability (one line each, status as of Aug 2026):**
  - **Langfuse** — open-source LLM engineering platform; prompt versioning with deploy labels (production/staging), SDK caching, non-technical editing in UI, tracing/observability (source: https://langfuse.com/docs/prompt-management/overview).
  - **PromptLayer** — visual prompt registry "built for engineers and domain experts alike": git-style versions/diffs/rollback, release labels, A/B routing, integrated evals (source: https://www.promptlayer.com/prompt-management/).
  - **LangSmith** — LangChain's managed platform: prompt registry, environment tags, playground, datasets/evals, tracing; natural fit for LangChain shops (source: https://www.langchain.com/langsmith; comparison: https://nearform.com/digital-community/prompt-management-systems-compared/ — secondary).
  - **Braintrust** — eval-first observability platform; raised **$80M Series B Feb 2026** (ICONIQ-led, ~$800M valuation); customers incl. Notion, Cloudflare, Dropbox (sources: https://www.braintrust.dev/blog/announcing-series-b, https://siliconangle.com/2026/02/17/braintrust-lands-80m-series-b-funding-round-become-observability-layer-ai/).
  - **Humanloop** — early leader, **no longer available**: Anthropic hired the founders/team and the platform shut down Sept 8, 2025; migrations went to W&B/PromptLayer/Agenta (sources: https://news.ycombinator.com/item?id=44592216, https://blog.promptlayer.com/humanloop-shutdown-guide-to-migrating-your-prompts-and-evals-to-promptlayer/, https://agenta.ai/blog/humanloop-sunsetting-migration-and-alternative). Good cautionary slide: the tooling market moves fast; the *practice* (version, test, own) outlives any tool.
  - Market churn note (secondary, single source — treat as UNVERIFIED detail): Helicone acquired into maintenance mode, Vellum pivoted, PromptHub winding down (source: https://www.getmaxim.ai/articles/top-5-prompt-versioning-platforms-in-2026/).
- **Evals as regression tests for prompts:**
  - **promptfoo** — open-source (MIT) CLI/library: YAML test configs, prompt matrices, side-by-side model comparison, regression tests in CI/CD, red-teaming; 23k+ GitHub stars, ~350k developers, used by teams at >25% of Fortune 500. **Acquired by OpenAI (announced Mar 9, 2026)** to fold into OpenAI Frontier; OpenAI states it "will remain open source under the current license" (sources: https://www.promptfoo.dev/docs/intro/, https://openai.com/index/openai-to-acquire-promptfoo/, https://techcrunch.com/2026/03/09/openai-acquires-promptfoo-to-secure-its-ai-agents/, https://www.cnbc.com/2026/03/09/open-ai-cybersecurity-promptfoo-ai-agents.html).
  - **Anthropic Console Evaluate tool** — test suites + side-by-side prompt-version comparison + expert grading (see Part C "test before promoting"; source: https://docs.claude.com/en/docs/test-and-evaluate/eval-tool). Anthropic's eval-design guidance (SMART criteria; exact-match, LLM-graded Likert, binary PHI-detection checks — the PHI example is directly relevant to med-device audiences) (source: https://platform.claude.com/docs/en/test-and-evaluate/eval-tool → "define success criteria / build evals" docs).
  - Concept to teach: an eval is a **regression test for a prompt** — a fixed set of inputs + expected properties of outputs, re-run whenever prompt or model changes. Defensible analogy: like re-running IQ/OQ test protocols after a process change.
- **A/B testing:** registries route a fraction of live traffic to a new prompt version and compare metrics before full rollout (PromptLayer A/B releases: https://www.promptlayer.com/prompt-management/; Langfuse labels support staged rollout: https://langfuse.com/docs/prompt-management/overview). For business teams the lightweight equivalent is the Console/eval side-by-side comparison.

## Part E — Governance

- **Prompts contain data, not just instructions.** A stored prompt often embeds supplier names, pricing, audit findings, draft CAPA language, patient-adjacent examples. Therefore: **classify and control the prompt library the same way you classify the documents whose content it carries** (course recommendation; grounded in the guidance below).
- **Enterprise AI acceptable-use guidance:** explicitly define data employees must never put into AI tools — PII, PHI, IP, source code, financials; anonymize/mask business data in prompts where possible; give concrete safe-vs-unsafe examples per role (source: https://www.tenable.com/cybersecurity-guide/learn/ai-acceptable-use-policy-aup). Once data is sent to an external tool "the organisation loses the audit trail and cannot reliably delete or retract it" (source: https://sosafe-awareness.com/blog/ai-prompting-mistakes-that-risk-company-data/).
- **No credentials/PII in stored prompts:** a shared prompt is a distributed document — anything inside it (API keys, passwords, employee data, patient identifiers) is distributed with it. Use {{placeholders}} so the sensitive value is supplied at run time by the person using it, never saved in the template (course rule; consistent with Tenable/SoSafe guidance above and with mail-merge analogy).
- **Vendor-side controls exist and are teachable:**
  - Microsoft: Prompt Gallery prompts live in the M365 Substrate **within the tenant boundary**, encrypted; admins can export users' saved/shared prompts (audit) (source: https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-prompt-gallery).
  - Google: admins can switch Gem sharing on/off (Admin console > Generative AI > Gemini app > Gems); shared Gems inherit Drive permissions (source: https://workspaceupdates.googleblog.com/2025/09/gem-sharing-gemini-app-workspace.html).
  - OpenAI: workspace admins control GPT sharing/publishing options and which external GPTs are usable (source: https://help.openai.com/en/articles/8555535-managing-gpt-access-in-enterprise-and-edu-workspaces).
  - Anthropic: skills should be treated "like installing software" — audit third-party skills (they can contain executable code); claude.ai custom skills are per-user, no central admin distribution; Enterprise offers skill content scanning (source: https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview).
- **Review shared prompts like documents:** owner, approval before team-wide sharing, periodic review — matches the admin/export/audit affordances above and standard document-control practice (course synthesis).
