# PART A — What the tools can actually produce (Aug 2026)

## A1. Claude — native file creation (xlsx / docx / pptx / pdf)

**What it does.** Claude (claude.ai web, desktop, mobile) creates and edits real Office files from natural language: Excel (.xlsx), PowerPoint (.pptx), Word (.docx), and PDF; it can also produce Python scripts, PNG images, and process CSV/TSV (source: https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude). Announced Sept 9, 2025; generally available Oct 21, 2025 (source: https://claude.com/blog/create-files).

**How it works (teachable mechanism).** Claude gets "a private computing environment directly in claude.ai" where it *writes and runs code* (Python/JavaScript) using common document libraries to build the file — i.e., the model doesn't "type" the spreadsheet, it programs it. Sandboxes are never shared between users and have limited network/container/storage resources (source: https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude).
- **Analogy (defensible):** Claude is less like a typist and more like a junior analyst with a locked-down laptop: it writes a small program that builds your file, runs it, checks the output, and hands you the result. Technically accurate — it is literally sandboxed code execution.

**Plans & limits (as of Aug 2026).**
- Available to **all Claude users — Free, Pro, Max, Team, Enterprise** — on web, desktop, and mobile; Team/Enterprise admins can disable it (source: https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude).
- **File size limit: 30 MB per file** for uploads and downloads; bigger PDFs can be processed through the computing environment without loading into context (source: same URL).
- Enable via Settings > Capabilities. Outputs can be downloaded or saved directly to Google Drive (source: same URL).
- Network access: on by default for Free/Pro/Max; **off by default for Team/Enterprise** (admins can enable with domain allowlisting — GitHub, NPM, PyPI, etc.) (source: same URL). Relevant compliance point for a regulated med-device audience.

**Vendor's own risk admission.** Anthropic's launch post warns: "This feature gives Claude internet access to create and analyze files, which may put your data at risk. Monitor chats closely when using this feature" (source: https://claude.com/blog/create-files). The help article adds that a bad actor could hide instructions in external files/websites that trick Claude (prompt injection) (source: https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude).

**Example use cases Anthropic markets:** financial models with working formulas, budget templates, project trackers, data cleaning + statistical analysis with charts, cross-format conversion (PDF→PPTX, notes→doc) (source: https://claude.com/blog/create-files).

## A2. Claude Artifacts — interactive HTML/React apps

**What they are.** Artifacts render Claude's output as live content beside the chat: Markdown/text documents, code, single-page HTML websites, SVG graphics, diagrams/flowcharts, and interactive React components (source: https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them). Available on **all plans including Free** (source: same URL).

**What business users build with them:** dashboards, calculators, trackers/checklists, simulations, flashcard/quiz apps, prototypes, small productivity tools (sources: https://claude.com/blog/build-artifacts; https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them).

**AI-powered artifacts.** Artifacts can embed Claude itself via a text-based API, making shareable mini-apps that answer questions, coach, quiz, adapt to input; when someone else uses your shared AI artifact, usage counts against **their** subscription, not yours (source: https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them; https://claude.com/blog/build-artifacts).

**Sharing & remixing.** Publish to a public link in two clicks; anyone with the link can view/interact; signed-in users can **Remix** (get an editable copy) (sources: https://claude.com/blog/build-artifacts; https://x.com/AnthropicAI/status/1810698780263563325).

**Constraints (important for training).**
- Artifacts are **self-contained, client-side pages** running in a sandboxed iframe: no server-side code, no databases, no arbitrary external API calls; external network requests are blocked by Content Security Policy (source: https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them for the sandbox model; constraint details widely documented, e.g. https://p0stman.com/guides/claude-artifacts-limitations). Exact allowlist details (e.g., which CDN/font hosts load) vary by surface and have changed over time — **treat specific CDN/localStorage behavior as UNVERIFIED per-surface detail**; the safe teaching claim is "assume self-contained: no external data fetches at runtime."
- Newer capability (as of Aug 2026, paid plans): published artifacts can get **persistent storage — 20 MB per artifact, text-only, personal or shared mode** — and Pro+ artifacts can connect to external tools via **MCP** (Asana, Google Calendar, Slack) with each user authenticating independently (source: https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them).
- **Analogy (defensible):** an artifact is like a laminated interactive one-pager — everything it needs is baked in when it's printed; it can't phone home for fresh data (unless explicitly wired to MCP/storage on paid plans).

Powered by GPT-5.6 per press coverage (same Bloomberg source).

# PART B — Task-specific prompting patterns (with authoritative backing)

## B1. Data analysis

1. **Always compute via code execution, never "mental math."** LLMs predict tokens; they don't calculate. Evidence: GPT-4 scored only **59% on 3-digit × 3-digit multiplication**, with accuracy falling toward zero as digit count grows ("Faith and Fate: Limits of Transformers on Compositionality," NeurIPS 2023 — source: https://arxiv.org/pdf/2305.18654; https://proceedings.neurips.cc/paper_files/paper/2023/file/deb3c28192f979302c157cb653c15e90-Paper-Conference.pdf). All four major tools now solve this the same way — by writing and running code (Claude sandbox: https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude; ChatGPT Python sandbox: https://help.openai.com/en/articles/8437071-data-analysis-with-chatgpt; Copilot Python-in-Excel: https://techcommunity.microsoft.com/blog/excelblog/whats-new-in-excel-april-2026/4502696). Prompt pattern: *"Use code to compute this — show the code and the result."*
   - **Analogy (defensible):** asking an LLM to do arithmetic in its head is like asking a brilliant colleague to multiply 6-digit numbers without a calculator — fluent, confident, and often wrong. Giving it code execution is handing it the calculator.
2. **Schema-first prompting.** Name the exact columns/fields before asking for analysis: "Columns: Lot_ID, Supplier, Defect_Count, Inspection_Date…". Microsoft's own Copilot tip: naming the columns you want analyzed "produces more accurate results" (source: https://support.microsoft.com/en-us/excel/copilot/copilot-in-excel-tips).
3. **Validation/reconciliation asks.** Build checking into the prompt: "After computing, reconcile totals against the raw file; report row counts before/after filtering; flag any dropped or null rows." ChatGPT's "View Analysis" (imports, transformations, plot parameters) and Claude's visible code both support auditability (sources: https://help.openai.com/en/articles/20001052-file-storage-and-library-in-chatgpt; https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude).
4. **Chart requests: state the message, not just "make a chart."** Weak: "chart this data." Strong: "Make a chart whose takeaway is *supplier defect rates diverged after the March process change* — choose the chart type that shows that; title the chart with that sentence." This transfers the assertion-evidence research (message-titles beat topic-titles for retention — source: https://www.writing.engr.psu.edu/ae_headlines.pdf) to charts.
5. **Interpretation guardrails in the prompt.** Standard statistical hygiene, stated explicitly: "Note correlation is not causation; flag any group with n < 30; identify outliers and show results with and without them; state confidence/limitations." (General statistical best practice; the small-n and outlier norms are standard quality-engineering statistics — no single canonical URL; frame as SPC/stats discipline the audience already knows.)

## B2. Spreadsheets

1. **Formulas: state exact column names and locations** — Microsoft's own top guidance for Copilot in Excel ("Name the columns or ranges you want Copilot to work with"; use clear descriptive headers) (source: https://support.microsoft.com/en-us/excel/copilot/copilot-in-excel-tips; https://support.microsoft.com/en-US/Excel/copilot/generate-formula-rows-and-columns-with-copilot-in-excel).
2. **Multi-tab workbooks with a README/assumptions tab.** Claude's file creation builds multi-sheet workbooks with working formulas (source: https://claude.com/blog/create-files). Prompt pattern: "Build a workbook with tabs: README (purpose, data sources, assumptions, date), Raw_Data (untouched), Calculations (formulas referencing Raw_Data), Dashboard. Never hard-code numbers a formula can derive." This mirrors financial-modeling separation-of-concerns convention (practice pattern — widely taught; no single primary URL).
3. **Cleaning messy data.** Describe the mess and the target shape: "This export has merged headers over two rows, dates in three formats, and totals mixed into data rows. Produce one clean row per record with columns X, Y, Z; list every transformation you performed." (Vendor-supported use case: data cleaning is a named Claude/ChatGPT capability — sources: https://claude.com/blog/create-files; https://help.openai.com/en/articles/8437071-data-analysis-with-chatgpt.)
4. **Ask for formulas explained before insertion.** Copilot's formula flow shows the suggested formula with an explanation before you insert it — turn that into a habit: "Show the formula, explain each part in one line, then apply." (source: https://support.microsoft.com/en-US/Excel/copilot/generate-formula-rows-and-columns-with-copilot-in-excel). Claude for Excel similarly highlights cell-level edits for review before finalization (source: https://claude.com/claude-for-excel).
5. **Trust calibration:** Microsoft's own 57.2%-vs-71.3% SpreadsheetBench number (source: https://techcommunity.microsoft.com/blog/excelblog/building-agent-mode-in-excel/4457320) = "the agent is a strong intern, not a signed-off spreadsheet."

## B3. Presentations

1. **Outline → doc → deck flow (Microsoft official).** Microsoft's guidance: write the content as a **Word doc structured with Styles** (headings, subheads); Copilot "will better understand your source document structure and how to break it up into slides," auto-creating slides from headings, tables, images — with speaker notes — then you review the draft (source: https://support.microsoft.com/en-us/office/create-a-new-presentation-with-copilot-in-powerpoint-3222ee03-f5a4-4d27-8642-9c387ab4854d). Works best under 24 MB, one file at a time (same source).
2. **Message-titles, not topic-titles (assertion-evidence).** Penn State's Michael Alley et al.: slides with a **succinct sentence headline stating the takeaway**, backed by visual evidence instead of bullets, produced statistically significant gains in comprehension and recall (p < .01) versus topic-phrase + bullet slides (sources: https://www.writing.engr.psu.edu/ae_headlines.pdf; https://peer.asee.org/assertion-evidence-slides-appear-to-lead-to-better-comprehension-and-recall-of-more-complex-concepts.pdf; overview: https://www.assertion-evidence.com/references.html). Prompt pattern: "Every slide title must be a full sentence stating the slide's conclusion (e.g., 'Supplier B's CAPA closure time dropped 40% after the audit'), not a label ('CAPA Results')."
3. **Audience + time budget in the prompt.** "12 slides max for a 15-minute QBR to non-technical execs; one message per slide; appendix for backup detail." (Prompting best practice consistent with vendor guidance to specify context/format — e.g., https://support.microsoft.com/en-us/excel/copilot/copilot-in-excel-tips's "the more specific, the better" and Anthropic's clear-direct guidance at https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/be-clear-and-direct.)
4. **Template/continuity constraints.** Claude for PowerPoint reads your template's layouts, fonts, colors, masters and preserves them (source: https://the-decoder.com/claude-now-works-across-all-three-major-office-apps/; https://claude.com/claude-for-excel — "uses your heading styles, slide masters"); Copilot drafts inherit the open template's theme (source: https://support.microsoft.com/en-us/office/create-a-new-presentation-with-copilot-in-powerpoint-3222ee03-f5a4-4d27-8642-9c387ab4854d). Prompt: "Use the attached corporate template; do not change master styles; flag any content that doesn't fit the layout rather than shrinking fonts."
5. **Speaker notes.** Ask explicitly: "Add speaker notes: 3-4 sentences per slide covering what to say, not what's on the slide." Copilot generates speaker notes automatically when building from a doc (source: https://support.microsoft.com/en-us/office/create-a-new-presentation-with-copilot-in-powerpoint-3222ee03-f5a4-4d27-8642-9c387ab4854d).

## B4. Writing & communications

1. **Most workplace writing requests are edits, not drafts — prompt accordingly.** NBER Working Paper 34255 ("How People Use ChatGPT," OpenAI + Harvard's David Deming, Sept 2025, ~1M conversations): writing is the largest work use (~40% of work-related messages), and **about two-thirds of work writing requests ask the model to modify user-provided text (edit, critique, summarize, translate) rather than write from scratch** (sources: https://www.nber.org/papers/w34255; https://www.nber.org/system/files/working_papers/w34255/w34255.pdf; https://cdn.openai.com/pdf/a253471f-8260-40c6-a2cc-aa93fe9f142e/economic-research-chatgpt-usage-paper.pdf). Teaching implication: the highest-value skill is *feeding your draft in with a precise edit instruction*, not asking for magic from a blank page.
2. **Hard length caps.** Give numeric limits ("≤150 words," "one page," "3 bullets max") — models comply far better with explicit numbers than vague "keep it short" (vendor guidance to be explicit/specific: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/be-clear-and-direct). Note honestly: models sometimes overshoot; ask it to count and trim.
3. **Voice matching from samples.** Mechanism is real and vendor-supported: Microsoft's "Draft Instructions" stores standing voice rules so Copilot email drafts "sound like you" (source: https://support.microsoft.com/en-us/topic/ask-copilot-to-make-email-drafts-sound-like-you-62cbb77e-2828-4ff2-826e-ca09b1f4e803); example-driven prompting ("multishot") is core Anthropic guidance (source: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/multishot-prompting). Practical pattern: paste 2-3 representative samples (a few hundred words total) + "match this voice; list 3 style features you extracted before drafting." **No vendor publishes a research-backed minimum word count for style samples — any specific number is practitioner heuristic, flag as such (UNVERIFIED as a hard number).**
4. **Difficult-news structure.** Pattern to teach: context → the news stated plainly (no burying) → reason → what happens next / what we're doing → invitation to discuss. This is standard business-communication practice (textbook territory, not vendor doctrine — present as craft guidance, not a cited fact). Prompt: "Draft a message delivering [news]. State the decision in the first two sentences. No euphemisms. Include next steps and one sentence acknowledging impact."
5. **De-jargoning.** "Rewrite for a reader outside quality engineering: define or remove acronyms (CAPA, PPAP, SCAR), reading level ~8th grade, keep technical precision in a parenthetical where needed." ChatGPT Canvas has a built-in **reading-level adjuster** (source: https://openai.com/index/introducing-canvas/ via https://help.openai.com/en/articles/9930697), and plain-language norms are codified in the US Federal Plain Language Guidelines (source: https://www.plainlanguage.gov/guidelines/).

## B5. Evaluations / LLM-as-judge

1. **Foundational research.** Zheng et al., "Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena" (NeurIPS 2023): strong LLM judges (GPT-4) reached **>80% agreement with human preferences — the same level as human-human agreement** — making LLM-as-judge a scalable, explainable approximation of human evaluation (source: https://arxiv.org/pdf/2306.05685).
2. **Known biases (same paper):** **position bias** (favoring the first answer shown), **verbosity bias** (favoring longer answers), **self-enhancement/self-preference bias** (favoring their own outputs), plus limited math/reasoning grading ability; some are mitigable (e.g., swap positions and average) (source: https://arxiv.org/pdf/2306.05685). Newer quantification: "Justice or Prejudice? Quantifying Biases in LLM-as-a-Judge" (source: https://arxiv.org/pdf/2410.02736) and "Self-Preference Bias in LLM-as-a-Judge" (source: https://arxiv.org/pdf/2410.21819).
3. **2026 state of the art:** "Reliability without Validity" (Norman, Rivera, Hughes, June 2026; 21 judge models, ~541k judgments) found simple agreement metrics **overstate judge quality** (kappa deflation 33-41 points on MT-Bench), judge rankings unstable across benchmarks, and a "consistency-bias paradox" — production judges can be highly repeatable (>0.95 test-retest) while carrying severe position bias; authors call for a Minimum Viable Validation Protocol (source: https://arxiv.org/abs/2606.19544). Teaching line: *a consistent judge is not necessarily a fair judge.*
4. **Pairwise vs absolute scoring — nuanced.** Pairwise comparison is generally more stable/sensitive than absolute 1-10 scoring for open-ended quality (easier task, less prompt-sensitive), which is why Chatbot Arena uses it (source: https://arxiv.org/pdf/2306.05685). But 2025 work shows pairwise is **more vulnerable to distractor exploitation** — preferences flipped ~35% under distractor features vs ~9% for absolute scores ("Pairwise or Pointwise?", source: https://arxiv.org/abs/2504.14716). Teach: pairwise for ranking candidates; rubric-anchored absolute scoring for pass/fail against a standard; ideally both.
5. **The rubric pattern (vendor-endorsed).** Anthropic's evaluation docs: define measurable success criteria; make rubrics **specific and empirical** ("The answer should always mention 'Acme Inc.' in the first sentence. If it does not, the answer is automatically graded as 'incorrect'"); constrain output ("respond only 'correct'/'incorrect'" or a 1-5 scale); **have the judge reason first, then grade** (source: https://docs.anthropic.com/en/docs/build-with-claude/develop-tests). Classroom pattern: *"Grade this supplier audit summary against this rubric (criteria + scale + example of a 5 and a 2). For each criterion, quote the exact sentence that justifies your score."* Quote-grounding makes grading auditable.
6. **Human-in-the-loop for consequential evals.** Zheng et al. explicitly propose a **hybrid framework of LLM judges plus human evaluation** (source: https://arxiv.org/pdf/2306.05685); Anthropic recommends testing judge reliability before scaling (source: https://docs.anthropic.com/en/docs/build-with-claude/develop-tests); the 2026 reliability literature (above) reinforces that consequential decisions (supplier scoring, personnel, regulatory text) need human sign-off. For a med-device audience: an LLM judge is *screening inspection*, not *final release*.

## B6. Interactive HTML — when to ask for an app instead of a deck or spreadsheet

1. **When to choose it.** Choose an interactive HTML artifact/app when the audience needs to *explore* (filter, sort, simulate what-ifs, self-quiz) rather than be *walked through* (deck) or *own the numbers* (spreadsheet). Vendor-marketed use cases: dashboards, calculators, trackers, simulations, flashcards/quizzes (sources: https://claude.com/blog/build-artifacts; https://gemini.google/overview/canvas/; https://workspaceupdates.googleblog.com/2025/05/gemini-canvas-quizzes.html). Rule of thumb for the class: *one message → slide; one dataset to own → spreadsheet; one question the viewer keeps asking differently ("what if…?") → interactive app.* (Framing is ours, capabilities are sourced.)
2. **Prompting pattern: data + interactions + audience.** Specify (a) the data (paste it or attach it, name the fields), (b) the interactions ("filter by supplier and date range; toggle between count and rate; sliders for assumption X"), (c) the audience/constraint ("plant managers on tablets; no external data connections; everything embedded"). Self-containment is a real technical constraint, not just style: Claude artifacts run sandboxed with no external API calls (source: https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them), so all data must be embedded at creation time.
3. **How business users share them.** Claude: Publish → public link, viewable without an account, remixable with one (source: https://claude.com/blog/build-artifacts). Gemini Canvas: Share & export → g.co/gemini/share link; caution — shared-data Canvas apps use a public Firestore DB visible to anyone with the link (source: https://support.google.com/gemini/answer/16419134). ChatGPT Work outputs "shareable web apps" (source: https://www.bloomberg.com/news/articles/2026-07-09/openai-unveils-chatgpt-work-agent-to-field-tasks-for-hours).
4. **Governance caution for regulated teams:** a public share link is publication. No confidential supplier data, patient data, or unreleased quality data in publicly shared artifacts/apps — both Google and Anthropic warn links are public (sources: https://support.google.com/gemini/answer/16419134; https://claude.com/blog/build-artifacts). Check whether enterprise plans restrict sharing before demoing.
